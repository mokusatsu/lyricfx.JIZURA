作成日: 2026-10-18（Asia/Tokyo）。本書の現行解析は計画登録時点の記録。2026-10-18に002の契約/検証基盤を追加した（末尾）。本番回避機能は未変更で、受入完了を示さない。

スキル導入コミット: 3c79480。実装タスクの正本は [task-list.md](task-list.md)、今回の解析記録は [AVOID-001.md](AVOID-001.md)。

## 1. 結論

現行の中央回避は、全画面の歌詞軌道に障害物を渡す方式ではない。固定の中央矩形から外れる小さい表示矩形を選び、その寸法で各レイアウトを再生成・描画・クリップする方式である。修正は固定矩形を円へ置き換えるだけでは成立しない。

新方式では、画面全体の座標系、歌詞の寸法、歌詞の軌道、手動で指定した表示矩形を分離する。回避領域は時刻から解決する制御データとして持ち、通常軌道は円を避け、円軌道系はその中心を基準に構成する。最終的な軌道の確定は、保存済み演出・詳細編集・シーングループ・サイズ記法の適用順と一体で扱う。

補助的に大量に敷き詰める反復歌詞は、利用者の追加指定に従ってレイアウト再設計から除外し、円形グラデーションマスクで回避領域だけを透過する。同一レイアウト内でも主歌詞は軌道生成、反復背景はマスクと役割を分ける。

登録レイアウト184種類を、基本16・拡張A26・拡張B25・拡張C34・拡張D34・表現セット42・中心基準7に分けて対応する。少数の代表例だけで全対応と判定しない。分類は作業分担案であり、個別の適応方式と合格証拠は後続タスクで確定する。184種類を一律に軌道再設計する意味ではない。各描画の主歌詞／反復補助／独立装飾を分類して対応する。

## 2. 要件と決定の出所

### 利用者の明示要件

- オーバーレイ先の演者を避ける歌詞軌道を、画面全体を使って生成する。
- 複数カットのシーンでも、それぞれの歌詞が回避する。
- 初期の円形回避領域は、画面中央よりやや上を中心にする。
- 円が中央なら上下左右、上なら左右と下、下なら左右と上を重点的に使う。
- 円軌道等は回避領域の中心だけを使い、その中心の周りに軌道を作る。
- 既存の前景・歌詞・背景の3トラックより上へ回避領域トラックを追加する。
- 回避要素を複数配置し、要素の編集ボタンから位置を移動できるようにする。
- このスレッドは現行解析・詳細計画・タスク登録だけを行う。
- 添付スキルをリポジトリへコミットして使用する。
- 各実装段階はGitHub Pagesへ出力した後、確認ポイントのリストを人間へ提示して確認を依頼する。公開元は利用者が設定したworkブランチ。
- 人間確認用に確認対象のキャプチャ画像を準備し、変更前後を視覚比較できるHTMLを生成する。各段階の公開物と確認依頼へ含める。

## 4. データ・座標・時間の契約案

### 4.1 保存するもの

プロジェクトに独立したlyricAvoidanceを追加する。グローバルの有効設定は既存lyricEffects.avoidCenterを唯一の正本として再利用し、autoPlacementとの関係も維持する。有効フラグを二重管理しない。

~~~json
{
  "lyricAvoidance": {
    "version": 1,
    "regions": [
      {
        "id": "avoid-default",
        "start": 0,
        "end": null,
        "center": {"x": 0.5, "y": 0.42},
        "radius": 0.2
      }
    ]
  }
}
~~~

- centerは出力の元ステージに対する正規化位置。半径はmin(W,H)単位。初期UIは位置編集を必須とし、半径編集UIは必須にしない。
- idは永続ID。並び替え・削除・挿入で変化しない。UUID等の発行は編集操作時だけ行い、plan/renderでは発行しない。
- 旧データにlyricAvoidanceがなければ決定的な初期要素を補う。明示的なregions:[]は復元時に補わない。
- 旧中央回避OFFは見た目を維持。旧ONの未ロック自動配置は今回の修正対象として新方式へ移行する。旧ONの自動結果の完全な絵一致は目標にしない。
- 手動area、lockedAreas、lockedEffectsを一括削除しない。再生成可能なautoEffectsとユーザーの編集を区別する。
- 読み込みは構造・有限数・ID重複・時刻・座標・半径・バージョンを検証する。未知バージョンや不正入力を黙って正常値に置き換えない。取り込み失敗時は編集前状態を保持する。
- 初期制限案: center各軸0..1、radius 0.02..0.45、要素数上限1000。画面端で円が一部外れる場合も元の円で判定し、可視ガイドだけクリップする。値はAVOID-002で固定。
- portableのJIZURA01とmanifest.version=1は継続可能。新しい入れ子のversionを追加する。旧アプリへのダウングレードでは新機能の見た目を保証しない。

### 4.2 時刻の解決

resolveAvoidanceAt(projectOrPlan, stageTime) を純粋な関数として設ける。結果はnullまたは {id,cx,cy,r,source} 相当。呼出順、再生方向、前フレームの状態に依存しない。

- 区間はstart <= t < end。境界の時刻では後の要素が有効。
- end:nullは次要素のstart、最後は最終plan.durationまで。explicit endは自身の終了時刻。start以外で自動延長しない。
- explicit endが次要素のstartを超える時間重複は編集時に拒否する。読み込み・MCPも同一の検証を使う。
- 空白区間、先頭要素より前、明示的な空配列、OFF、autoPlacement=falseは回避なし。初期要素が全長をカバーするので、旧機能の常時回避は自然に移行する。
- 要素の追加は既存要素を分割する操作として開始できる。end:nullなら次のstartで自然に区切れる。explicit endを持つ要素の途中に挿入する場合は元の終了短縮を含めて1回のUndoにする。
- 出力長の短縮はplan側の可視範囲を切るだけで、保存された後半要素を消さない。再延長で戻る。制御トラックだけを理由に作品の長さを伸ばさない。
- 秒の保存精度とUIのフレームsnapを区別する。内部計算途中で繰り返し丸めない。最短区間の提案は0.04秒（既存境界操作と整合）、最終値は契約fixtureで決める。
- 新モデルに同時複数人物を入れない。将来必要なら別バージョンで複数円を返す契約へ拡張する。

### 4.3 円の幾何学

ステージ座標は C=(cx*W,cy*H)、R=radius*min(W,H)。正規化x/y空間で距離を計算してはいけない。16:9、9:16、21:9、1:1、4:5、任意videoSizeで真円を維持する。

通常軌道では文字の中心点だけでなく占有範囲を検査する。矩形Bと円の場合、円中心からB上の最近点までの距離とR+余白で判定する。回転・せん断・透視変形は変換後ポリゴン、または保証方向に余裕を取った包絡を使う。文字列の外接矩形一個で円環を判定すると中心穴も衝突扱いになるため、円軌道系と混同しない。

余白は短辺比例と出力ピクセルの最小値を使う。描画縮尺、文字幅、stroke、ルビ、影、強調・抑制サイズ、char/piece変形の影響を分類する。既存J.drawItemの返すbboxは完全な画面上インク境界ではなく、独立した幾何学オラクルが必要。

## 5. 軌道生成と描画の設計

### 5.1 表示矩形と軌道を分離する

- 手動areaの従来座標系・clipは維持する。
- 新方式の自動歌詞は全ステージW/Hをlayoutへ渡す。自動配置を表すための小さいareaを作らない。
- cutにはJSON化可能な軌道記述（例: placementTrajectory）を独立フィールドで保持する。paramsはエフェクトのパラメータであり、回避の生成キャッシュ置き場にしない。
- 文字のサイズ・語順・時間・姿勢・軌道・レイアウト固有装飾の結合関係をadapterで表す。プレート上の文字だけを動かしてプレートを取り残さない。
- 小さいオフスクリーン画像に従来演出を描いて縮小配置する方式へ戻さない。主歌詞を円形マスクで消すだけでは完了条件を満たさない。補助的な大量反復歌詞には5.7のマスク方式を使う。
- autoPlacement=trueかつavoidCenter=falseの従来自動areaも無断で全面改造しない。新方式は対象条件でだけ使う。

### 5.2 共通adapter契約

提案する責務は、prepare(cut,fullStage,style)、sample(localTime)、bounds(stagePose)、applyPlacement(stagePose)。名前は実装時に調整可能だが、次の契約を固定する。

1. レイアウトは基準形状・読み順を持つitem/groupと、必要な固有装飾を定義する。描画ごとにprimary（主歌詞・ルビ・意味のある注釈）、tiledAux（補助的な大量反復）、independentDecorを明示し、附属プレート等は所有する描画に紐づける。
2. enter/hold/exit・文字別・破片別変形を加えた姿勢とcameraの合成順を定める。
3. 回避は最終ステージ座標で検証する。親canvas、affine helper、cameraの変換を二重適用しない。
4. 求めた安全な経路を純粋に評価して描画する。描画後のbboxを次フレームの状態として学習しない。
5. 固有装飾は紐づくitem/groupと一緒に移動する。全画面背景・HUD・演出用の独立装飾は別責務として扱う。
6. 結果に対応方式・検査対象・制約不足の理由を記録できる。無対応のレイアウトを成功扱いしない。

mainDrawだけの一律補正は、env.drawによる主歌詞の注釈、affine描画、文字を貼った3D面、drawProgram、直接Canvasテキストを取りこぼす。env.drawや文字の反復回数だけを根拠に主歌詞／反復補助を判別しない。全体平行移動だけでは画面両側を使う流れる軌道も作れない。基本経路を共有し、必要なレイアウトは個別adapterを実装する。

### 5.3 通常軌道

- 円の外周に沿う上・下・左・右の通路と、画面端・各文字幅を考慮した候補を生成する。円のbounding boxだけで空き領域を4つの矩形に切らない。
- 終点だけでなく区間全体が安全な曲線を生成する。始点・終点が円外でも、その間の直線が円を横切るケースを必須試験にする。
- 中央判定のデッドバンド案は|cy-.5|<=.05。中央は上下左右を候補にし、外では上下の重みを連続的に入れ替える。偏りを確率・空き面積・直前配置のバランスとして定義し、フレームごとに再抽選しない。
- 中央・上・下の比較試験では、障害物なし/対称な画面で同じ100seed集合を使う。中央で4方向がすべて使われ、上では下が上より、下では上が下より多く選ばれることを判定する。
- 任意の左右位置でも幾何学的に回避できる。空きがない方向へ重みだけで押し込まない。
- フォントを一定下限まで縮めて帳尻を合わせる処理は、今回の主解決にしない。経路変更→複数通路への分配→安全な静的配置の順で候補を検討する。
- 明示サイズや画面全体を占める固定物のため解がない場合は、制約不足を記録し、手動値を勝手に破棄しない。中央回避成功とは判定しない。出力時の扱いはAVOID-002で明文化する。

### 5.4 円軌道系

初期の対象候補: ring、orbit、spiral、arcTop、circleWords、knPathRide、knGearWords。名称で自動判定せず、一覧へ明示登録する。円窓circle、背景の円、カメラorbitDriftは別責務である。

- 基準点を回避領域の中心へ移す。半径・周回速度・位相・文字サイズ・向きはレイアウト固有値を使う。
- 回避半径だけを変えても主歌詞の円軌道の形・位置は変わらないことを試験する。同じcutにtiledAuxがある場合、その透過マスクは半径を使う。軌道の中心専用契約と混同しない。
- spiralの現在の重心補正、arcTopの円中心と弧の見た目の中心、複数歯車の中心については、回転中心を契約として定義する。見た目のbbox中心を代用しない。
- グループ中の複数円軌道も共通の回避中心を参照し、位相・レイヤー・半径の調整は別の歌詞間配置の責務にする。回避半径で軌道を膨らませない。
- 回避領域中心の切替は同じ時刻に反映する。中心が端にある場合の従来の見切れは、通常軌道の安全性と別に評価する。
- 強調は今回の確認済み例外に従い、新しい回避由来の中心変更も適用しない提案とする。実装前に強調と円軌道の優先順位をfixtureで固定する。

### 5.5 表示時間と演出の時計

- 回避要素の選択は作品の実時刻t。歌詞の動きの量子化は既存tqを維持する。中心切替をkomaの次フレームまで遅らせない。
- 色収差のlag、ghost pre-roll、renderStart、displayEnd、手動end、transitionで旧カットを描く再帰呼出しも考慮する。
- 1フレーム内の全passへ同じ回避時刻を渡す。残像の動きはtpでも、旧回避領域へ戻して描かない。
- transitionの旧画像を作る際も回避選択の実時刻を引き継ぐ。単に通常frameだけへresolverを足す変更を禁止する。
- camera、transition、post-FXが文字を中央へ移す組合せは、adapter／安全な効果パラメータ／対象レイヤー処理のいずれで担保するか対応表に記載する。全画面post-FXを検査から落として「侵入ゼロ」と主張しない。
- 主歌詞の実体・ルビ・意味のある注釈・主歌詞を載せた面は軌道の検査対象とする。大量反復のtiledAuxには軌道の非侵入条件を課さず、5.7のalpha条件を検査する。背景・HUD・独立の装飾線を全部避ける要求へ拡大しない。にじみやglowの低alpha境界はAVOID-002で判定閾値を定める。

### 5.6 複数カット・手動編集・ロック

- 回避区間の境界で描画上のepochを分けても、歌詞のline/part、歌詞時間、カット数、timelineLinks、イベント所有者を分割しない。
- 各epochの同時表示カットを考慮する。グループのcut.start～slotEndだけでなくrenderStart～displayEndが対象。
- 別の時間にしか存在しない円を全部合体して避けると空きが過小になる。epochごとの制約を使う。
- シーンの各カットに軌道を持たせる。全シーンを一つの小矩形へ詰め直さない。
- 既存の歌詞間重なり強度、前景回避強度、背景窓、強調・抑制を同時に評価する。強調は円・前景の例外であり、歌詞間配置の意味まで解除しない。
- explicit details.area、行のarea、lockedAreasは優先する。競合を検出して記録し、自動的に手動へ分類し直したりロックを解除しない。
- 新しいロックは軌道と対応schemaもスナップショットへ保持する。回避要素を動かした際はロックした歌詞を動かさず、干渉を表示する案とする。
- サイズ記法による寸法指定を小さな描画viewportと混同しない。記法の大きさを保ったまま軌道を生成する契約をAVOID-002で決める。解がなければ明示的な競合として扱う。
- seedは既存の効果seedと配置seedを分離して使う。円の移動で演出・色・音楽イベントを再抽選しない。関係のない時区間とロック済みカットを変えない。

### 5.7 大量に敷き詰める補助歌詞のマスク

この部分はレイアウト再設計対象外。専用の[AVOID-018](AVOID-018.md)で、描画役割の分離と透過だけを実装する。

- [20IDの静的レビュー](evidence/AVOID-001/auxiliary-role-review.md)を実施。確認済みの例: tileの敷き詰め行、marqueeの反復帯、glossのbgText。tileの中央の主歌詞・主歌詞の箱、marqueeの主行、glossの主行と注釈はこの除外に含めない。意味のある円環文字や主歌詞そのものの反復も、名称・見た目だけでtiledAuxにしない。
- マスク前の反復行の位置・行数・間隔・動き・seedを全ステージ寸法で維持する。旧小矩形内の結果との画像一致ではなく、同じ全ステージ入力のマスク有無で比較する。円の移動で反復の経路を再生成しない。
- 距離d、回避半径R、ぼかし幅Fに対してalpha係数はd<=Rで0、R<d<R+Fでsmoothstep(0,1)、d>=R+Fで1という案。Fは短辺の0.04を初期案としAVOID-002で固定する。新しい半径・ぼかし幅の編集UIは追加必須にしない。主歌詞用の安全余白とは分ける。
- cameraやghostを含む変換後のステージ座標で真円を作る。マスクは実時刻tのresolverを参照し、境界では全passが新しい中心を使用する。OFF・gap・強調歌詞・手動/lockの扱いは共通の適用条件に従う。強調cutの補助反復も自動でマスクしない。
- 反復補助だけの一時描画面へalphaマスクを適用する。既存背景・前景動画・主歌詞・主歌詞の箱・独立装飾を含むcanvas全体にdestination-outを掛けない。反復帯に附属する板は役割表で一緒に処理するか明記する。背景そのものを円抜きしない。
- 主歌詞と補助歌詞が交互に描かれる場合も元の描画順を保つ。全ての補助歌詞を一律に最背面へ移さない。blend、cut opacity、frontmost、既存source/cut mask、人物遮蔽との積算順をfixtureで固定する。独立canvas化でmultiply/overlayの結果が変わる点をAVOID-004で先に検証する。
- transition/post-FXが反復をコピー・移動する場合、移動後も役割を保持してマスクを適用する必要がある。背景と主歌詞へ平坦化した後の全画面マスクでは解決しない。非分離のFXで成立しない組合せは対応表へ記録し、AVOID-002/004で方式を確定するまで対応済みにしない。
- 反復字ごとに全画面canvasを確保しない。再利用バッファを基本にし、同時グループ・transition再帰の寿命を分けて上限を測る。マスク外の描画と主歌詞・動画が不変であること、内側が透明、境界alphaが単調であることを独立画像試験で確認する。

### 5.8 最終計画の確定とフォント寸法

軌道確定処理は、全ての詳細/lock/サイズ記法/customラッパーに加え、UI composePlanのmedia/foreground・durationOverride適用後を最終入力にする。J.planだけを利用するプレビューや外部経路にも、同じ確定APIを利用できるようにする。暫定planと最終planの区別を明示し、確定処理を繰り返しても結果・seedが変わらない設計にする。尺の再延長、前景の追加、short preview・タップ入力時の尺変更も無効化対象にする。

文字計測はフォントのロード状態・言語・weight・glyphを含むrevisionと結び付ける。fallbackフォントで作った軌道を本来のフォントで描き続けない。ロード完了で必要範囲を再計算し、ロード失敗時は使用したfallbackと診断を固定する。書き出しは使用フォントの確定後に最終計画を作ってsnapshot化する。非同期処理の完了順で古い編集結果を反映しない。AVOID-004/012/013/016で一貫して扱う。

## 6. 第4トラックと編集UI

回避 → 前景 → 歌詞 → 背景の順。制御トラック用のdescriptorを設け、既存3層の分岐を必要範囲だけ拡張する。メディア素材・合成モード・コピー元・空の歌詞カットへ偽装しない。

- 一覧: 有効区間、位置の簡単な表示、直接アクセス可能な編集ボタン、削除を提供する。複数要素を置き、移動・開始/終了の調整・区間分割を行える。
- 新規要素のIDと参照を保存し、再生成されたindexを永続キーにしない。
- 境界参照はa:<id>等で型を識別する。初期版でも既存boundary linkと連携できるよう契約を定め、リンク先のlimits、削除、出力長短縮、Undoを検証する。実装しない操作を既存のlyric/mediaへ流さない。
- end:nullの右端はresolverの計算結果であり、保存値そのものではない。右端を手動で動かす操作はexplicit endへ変換する案とし、「次の要素まで」でnullへ戻す。次要素のstart変更による追従と、リンクからの同時更新を1トランザクションで検証する。
- 既存の「現在位置で挿入」「ここで終了」「次の要素まで」への参加範囲を明示する。画像選択・演出再抽選・frontmostは制御トラックには表示しない。
- 位置編集: 選んだ要素の中心をドラッグ、数値入力、キーボードで変更。編集中はdraftだけを変更し、適用で1つの履歴、取消/Escapeで保存・履歴・時刻を戻す。
- 表示上の円は元ステージからCSSへ正しく変換する。widthとheightへ同じ百分率を入れると横長画面で楕円になるため禁止。
- ガイドの表示状態と回避の有効状態を分離する。ガイドはUI overlayで描き、Rendererの出力・サムネイル・PNG/MP4へ焼き込まない。
- 新方式でcut.areaがなくても、歌詞の選択枠を毎回全画面へ戻さない。軌道由来の選択領域を別に供給し、全画面clipとして再利用しない。
- 320/390px幅、拡大1～8倍、スクロール、devicePixelRatio、touch、フォーカス、日英表示、書き出し中の操作抑止を検査する。4段化でプレビュー高さが負になることを防ぐ。

## 7. 保存・キャッシュ・外部連携

- normalize/merge、defaultProject、JSON/portable、localStorage、新規作成、Undo/Redo、MCP import/patchで同じvalidatorを使う。
- 設定プリセットは回避ON/OFFを扱ってよいが、曲固有のregions・id・時刻をコピーしない。設定適用時は現在のregionsを保持する。
- お気に入り・演出コピーへ回避軌道・回避ID・絶対配置を入れない。コピー先の回避領域で再計画する。
- autoEffectsのseed-only keyに回避データを混ぜてすべての演出を再抽選しない。配置の派生キャッシュは別キーとし、必要なtext/font/size/layout/camera/region/version/aspect/time範囲とフォント計測revisionを含める。反復用canvas・マスクbitmapは保存せず、決定的に再生成する。
- previewのfastモードと通常exportは同じ位置を返す。fastを理由に回避判定を飛ばさない。
- PNG/MP4は同じ時刻・同じscene planを使用。MP4比較は圧縮済みピクセルの完全一致ではなく、エンコード前frameと復号後の許容差を使う。
- 縦型short exportは元画面で回避した結果を変換する。新しい9:16座標で回避を二重適用しない。素材動画の座標への対応とは分ける。
- MCPのproject patchは回避の不正区間を受け付けない。stateに制御要素を専用欄で返す案とし、既存3層のcut APIに誤投入しない。
- AEに新しい軌道を渡しても現行AEは解釈できない。初期実装では対応capabilityを明示し、新方式を含むAE出力は明確な未対応エラーにする案。旧方式・新方式OFFの既存出力は維持する。黙って小矩形/中央配置へ劣化させない。AEの完全再現は別案件として実機検証と一緒に計画する。

### 将来の動画分析との接続点

外部解析はソース時刻・画像座標の結果を直接regionsへ流さない。素材ID、ソース時刻、区間、信頼度、解析方法を持つ中間結果から、mediaVideoTime、カットstart/trim/loop、fit/crop、placement、cameraを通してステージ時刻・座標へ変換するadapterを置く。

今回の固定領域を返すresolverをそのまま利用し、後続schemaではregion内のpositionAt(t)等に拡張できる形にする。推論ライブラリ追加、モデルのダウンロード、人物検出精度、補間UIは今回の実装タスクへ混ぜない。人物マットと回避円の正本を二重に持たず、取り込んだ結果は通常の編集可能な回避要素へ変換する方針。

## 8. 実装順・検証・リリース条件

各工程は [task-list.md](task-list.md) から詳細へ辿れる。後続実装は17件。基盤→通常/円軌道adapterと描画役割分類→反復補助マスク（AVOID-018）→グループ統合→保存→トラック→編集→出力→全体検証の順に進める。追加した018は発行済みIDを振り直さず、依存順では012の前に置く。adapterの各タスクは技術的には独立だが、運用上は1タスクずつ扱う。

新経路は開発中に通常利用の既定経路として途中まで有効化しない。段階確認専用のPagesページでは、対応済みのfixtureに限って新経路を明示的に実行できるようにする。未対応レイアウトを自動選択から黙って落としたり、旧小矩形経路へ黙って戻したりしない。全stock layoutに実装/検証の状態が付くまで、機能のリリース判定を行わない。

### 段階ごとのGitHub Pages確認

[共通運用](pages-human-review.md)、[比較画像・HTML契約](visual-review-comparison.md)、[確認依頼テンプレート](templates/pages-review-request.md)を全17段階へ適用する。各タスクに固有の3項目と撮影対象を登録済みで、実装後に実URL・UI名・サンプル・期待結果へ具体化する。002で公開確認ページとキャプチャ/比較HTML生成の最小構成を作り、モデルだけの003も図と時刻選択で人間が確認できるようにする。

変更前の版/fixture固定・撮影→実装・自動試験→日英HTML生成と同条件の変更後撮影→比較HTML/manifest生成・検証→workへコミット・プッシュ→Pages反映と版/全画像の一致・表示確認→人間へ比較URL付きチェックリスト提示→回答記録の順。公開処理の成功だけで合格にせず、未回答を承認とみなさない。確認待ち中は対象版を別段階で上書きしない。公開元がworkであることは利用者の設定報告を採用しており、設定APIの読み取り成功を主張しない。

画像は同じ歌詞・seed・寸法・フォント・実時刻で取得し、enter/hold/exitと境界前後、透過PNG、UI/出力の違いを必要なケースで分ける。全51項目から版付き比較HTMLの画像ペアへ辿れるようにする。新UIが旧版に存在しない場合や仕様見本は明示し、未実装を完成画像にしない。静止画で全軌道・保存・性能を保証せず、既存の独立オラクル・実操作検証を併用する。最終017では段階前後と機能導入前からの累積比較を分けて示す。

最終017では先行段階の判定と自動検証を満たした候補版をPagesへ公開し、既定で有効な新方式を人間が確認してから完了とする。これにより「人間確認前には公開できない」「公開しないと人間確認できない」という循環を作らない。

幾何学検証は生成側とは独立したオラクルで行う。Bezier等は制御点やswept boundによる保証、または誤差上限を明示した適応分割で検査する。数フレームの抜取だけを「全軌道が安全」と呼ばない。描画テストはconsole.warnの内部例外も捕捉する（Rendererは例外をcatchして描画を継続する箇所がある）。

性能はAVOID-002で固定fixtureの基準値を記録し、AVOID-004/017で同条件比較する。100要素/100カットの標準、1000要素と長い残留グループの負荷を分け、候補数・分割数・キャッシュ上限を設ける。数値予算の案はplanning p95で基準の2倍以内、描画の追加処理p95で同環境3ms以内。これは現状達成値ではなく初期受入案。

ロールバックはコミット単位で新経路の利用を戻せる構成にし、保存した回避要素を消す処理にしない。schemaが理解できない旧版の見た目が再現できると誤認させない。今回の計画更新ではアプリ実装・Pages公開設定の変更・PR作成は行わない。計画・タスク・証拠は依頼済みのworkへコミット・pushする。後続の各実装段階では、利用者指定に従って同ブランチからPagesへ公開してから人間確認を依頼する。

## 9. 実装前に確定すべき残論点

1. 初期中心/半径、中央判定帯、安全余白、数値上限・性能予算の最終値。
2. 手動/lock/巨大な明示サイズと回避が両立しないときの通知と出力方針。自動で縮小・解除はしない案。
3. 円軌道系の中心語・円盤の保持、強調例外との優先順位、7候補の最終分類。
4. camera/transition/post-FXと文字のにじみに対する保証範囲・alpha閾値。検査範囲外を黙って成功に含めない。
5. 初期のAE未対応エラー方針と、将来AEで同一軌道が必要かの切り分け。
6. 反復補助の全ID/描画単位分類、附属帯の所有、マスクのぼかし幅、非分離のpost-FX/transitionに対する具体的な合成方式。20IDの静的レビューを根拠に役割を確定する。rainのtrailやwordCloud等の散布表現、残りの未レビューIDを一律に除外しない。

これらは計画登録時に未決事項として明示したもの。002で固定した項目と後続担当は末尾およびcontract.sourceKindsを参照する。既存の不足をアプリ修正で先回りせず、契約タスクで決定と根拠を記録する。実装可能性や全レイアウト対応を、この解析だけで検証済みとはしていない。
