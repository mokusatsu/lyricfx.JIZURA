Schema: `{codec,tree,aliases,scalars,nullPrototypes,rootSpecial}`. The first ordinary dense array/plain object is inline; each repeated reference becomes null plus `[parentFirstPath,key,targetFirstPath]`. Special scalar property/array slots become null plus typed repair records; root undefined/-0 uses a separate root marker. Null-prototype FIRST objects have path metadata. Root is canonical path[]. Object keys are string path components, array indices numbers. Data keys cannot collide with the protocol because all metadata is outside `tree`; hostile names such as __proto__,constructor,toString must be resolved through captured own-data descriptor helpers and assigned via own-data define, never inherited lookup/setter dispatch.

The offline reference parses the estimated wire, patches only listed metadata, and re-encodes with the original v1 encoder. Both complete v1 strings are exactly equal to the old originals: value, object/array key order and all alias topology are covered. This is a two-record representation proof, not a production decoder, generic unsupported-shape oracle or acceptance claim. The old payload strings were reconstructed earlier from saved full alias graphs and source originalCuts and match actual old payload byte ledgers; their hashes and all provenance remain explicit.

Parents and targets are paths to inline FIRST occurrences, so repairs never need to traverse through an alias placeholder. First traversal records a path before descending but rejects active-stack cycles before recognizing prior references. Repeated aliases stop descent, preventing metadata duplication beneath shared subtrees. All target containers exist after native parse; null-prototype and scalar repairs can precede alias attachment. Updating existing own slots preserves insertion order and array density. This source domain still requires old strict plain/dense/own-enumerable-data/symbol/cycle/nonfinite/prototype rejection; nativeJSON behavior alone is insufficient because it silently drops unsupported values and collapses -0.

If selected, the first production prototype should be payload-only. Input/options/lineage v1 graph bytes, full dependency collection, second verify, source/adapter/font/context/runtime identity, normal plan-only freeze/signature and32entry/128MiB/512header limits remain unchanged. Do not fuse freeze or reuse prior frozen finalized objects: native parse gives a fresh tree for every read, metadata recreates within-read aliases, normal finalization freezes the same reachable plan graph while detached originalCuts remains mutable unless reachable from plan. New parsing/path helper identities need captured-native guards or explicit bypass/fallback and corresponding negatives; no helper guard is removed.
