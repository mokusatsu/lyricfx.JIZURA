# AVOID-007 visual-a 画像・動き照合

対象は `work/avoid007-native/local-20261022-01` の rain / hanging / bounceLine / elastic / neon / bubbles / keycaps / stickerBomb。manifest 実SHA256は `c0c64e78bbbfc33761e378acd21fd7899cd59353e3a1ac1dcb02e6c9c2a77274` で指定値と一致。各16 MP4と全64 native key PNGの実SHAをmanifestと照合し全件一致。各ファイルの実値、条件、probe結果、decodeコマンド、実際に見た画像と検査画像SHAは `visual-a-metadata.json` に保存。

**結論:** 見た範囲で新しい欠字・読順反転・文字と所有板の分離を確認しなかった。ただし hanging の札端重なりと、elastic の単一斜め軸から2軸への構成変更は所見として残る。elasticの「元の単一軸を厳密保持した」とは判定しない。全IDを無条件合格にした記録ではない。

## 方法と実sample

全8IDのbefore/after MP4から、ffmpeg入力decoder `-threads 1`、PNG出力 `-threads 1` で frame **0,6,12,24,36,48,72,90,95** をdecodeした。対応時刻は **0,0.25,0.5,1,1.5,2,3,3.75,3.958333…秒**。実MP4のprobeは各96frame / 24fps / 4秒、elasticとstickerBombは3200×1080、残りは1920×1080。全ケースの文字「風の先へ」、seed704、円cx=.5/cy=.42/r=.2(shortside)をmanifest条件として確認。

さらにrain/keycaps/bubbles/elastic/hangingは両sideで **1,2,3,4,5,8,10,14,16,18,20,22,91,92,93,94** をdecodeして出現初期・退出の密な補助照合を行った。時刻は各frame/24秒（正確な浮動値はmetadata）。主9時点シート8枚、追加16時点シート5枚を実見した。シートは `scratch/avoid007-visual-a/b25-<ID>-contact.png` / `b25-<ID>-dense-contact.png`。全元画像は変更していない。シートは検査用で、公開MP4の生成方法を代替するものではない。

直接開いた追加画像は decoded hanging-after f48 (`b25-hanging-after/06.png`)、native neon before/after f36、native elastic before/after f15、native stickerBomb before/after f36。ツール表示上、主シート1280×2214は1184×2048、native3200×1080は2048×691へ縮小されたため、原寸ファイルを開いた事実と画面で全ピクセルを等倍精査したことは区別する。hanging decoded f48とneon nativeは1920×1080で実見。

## 限界

これは同一条件の**sample画像の順次照合**であり、ブラウザ連続再生/性能/全時刻安全証明ではない。調べたsample間で明らかな不自然な離散跳躍は発見していないが、未sample frame内の跳躍を排除していない。特にelasticの極初期の急な横開きは元にもある。連続運動を無条件に「滑らか」とは認定しない。

円の描画overlayは素材にないため、画像から正確な接触距離や幾何安全を認定しない。数値safe判定は独立幾何試験担当へ委ねる。rain grid以外の所有板/紐/点/枠は今回の比較対象とし、AVOID-018の未実装補助maskによる円侵入は本件欠陥に混ぜていない。AA/hinting差・固定CSS＋native実効scale再設計とneon有限stroke化は事前宣言条件として扱った。
