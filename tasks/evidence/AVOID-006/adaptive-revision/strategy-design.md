# AVOID-006 adaptive revision: approved implementation design

Implementation model: gpt-6.1-sol / medium. Baseline HEAD06b87459822ac5bc6395e20b8eeb4a47cf12cb57, clean. The parent owns task/status/review records. This revision remains006; main-app activation belongs to017. Old review bundles remain immutable.

## Hard requirements and deterministic selection

Only justified, subtitleBar, splitScreen, sideways, panels, filmstrip, quote, ticket may adapt, and only when their existing joint-native translation is insufficient. Existing safe native segments and the other18 adapters remain unchanged. API: finalizePlacementPlan(plan,{layoutsA:true,layoutsAAdaptive:true}). Native source cut/text/lineText/note/params/seed/timing remain unchanged; derived segment composition describes rendering only. Same input/font revision produces the same first admissible candidate. Selection is fixed within each region. No per-frame repair, score search, new primary masks, whole-stage scaling, or automatic product activation.

Hard constraints precede all strategy comparison: complete source lyric coverage/order, all meaningful attached metadata, owning plate/clip/contrast, source reveal order/clocks, analytic whole-interval circle clearance and held visibility. First valid candidate in declared ID-specific order wins. attempts record actual candidates/rejections, including readability and resource failures. At most64 reconstructed candidates per cut/region; a bounded pool may share measurements across regions. Small corner circles are diagnostics, not the normal-radius acceptance example.

## Readability and quality metadata

New reconstructed primary size >=max(18px,.035U); meaningful secondary >=max(12px,.020U), U=min(W,H). Existing native-safe candidates are never invalidated by these new floors. Native size below floor permits no further shrinking; failed reconstructed floor yields a diagnostic rather than success. Discrete reductions .95,.90,.85,.80,.75,.70 only. Explicit lyricSize and explicit contentScale prohibit reduction; manual/notation areas and locks retain existing priority. Suppression intrinsic size remains intrinsic.

Record separate quality fields: fontScale/minPrimary/minSecondary, spacing/linebreak changes, owned-shape dimension changes, path direction/amplitude changes, semantic-unit moves, source coverage. Decorative length/padding reduction is not reported as font reduction. All rebuilt geometry gets newly measured ink/AA/camera bounds; no stage bitmap transform implements a candidate.

## Exclusion, provenance and no missing lyrics

Failure yields excluded-during-avoidance for that effect and no-certified-composition if no certified alternate exists. Do not delete a cut, blank text, change timing/seed, or call conflict safe. Automatic fallback is permitted only with proven automatic layout provenance captured from actual project inputs; explicit layout fixtures/overrides and lock/manual never silently substitute. Selection integration remains017. Staged API exposes exclusion and preserves original lyric-bearing rendering with honest conflict diagnosis if no certified composition is available. A successful alternate is not counted as a successful original-ID composition.

## Approved user revision: moving entrance/exit may pass the circle

The latest user explicitly allows temporary passage during entrance and exit. Prefer the unchanged native joint solution with phase-specific relaxation before any source recipe. This does not relax static lyrics merely fading/revealing, and does not permit hold-time intrusion.

Every event/pass is classified using actual native motionTime, while realTime selects the avoidance region. Only source-tagged moving events may relax. quote marks move until.52s; body and attribution stay strict at all times. filmstrip entry ends at.6s; its persistent native drift remains in the complete hold envelope. ticket body/stub entry ends at.5s; native body exit rotation (only for nonzero tilt) and stub tear are geometric exit motion. sideways companion slides until.65s; rotated main/divider stay strict. justified, subtitleBar, splitScreen and panels have no relaxation simply because alpha or clipping changes. Moving source exit begins at cut.end-cut.outDur. Entry time is relative to cut.start. Intersecting hold/region interval must contain at least.04s; otherwise NO_HOLD_WINDOW, not all-time passage success.

Trajectory status safe-hold / certified-hold-adapter is distinct from safe / certified-bounded-adapter. safetyScope=stationary-strict-moving-entry-exit-relaxed, holdWindow and native-clock relaxedWindows are explicit. Observations preserve realTime, motionTime and pass, all polygons, strictPolygons, relaxedPolygons, strictCircleClear, rawCircleClear and each actually relaxed event/motion/phase. A ghost pass cannot excuse a main-pass hold collision. Full native envelopes still bound relaxed motion; strict hold envelopes bound every other event. The native ltb drift range includes maximum1.6/24 ghost lag plus two quantization steps on both ends. This conservative range does not enlarge an event's allowed entry/exit window.

## Exact computation reductions (performance candidate)

The owned-text validation prepass invokes the same native source renderer with the same text geometry, source ownership, transform/clip state and event/glyph ceilings. It omits circle/arc/rounded-rectangle hull construction only for ordinary finite, well-conditioned recipe coordinates. Uncertain shapes or diagnostics force the original full recorder, preserving measurement failure precedence. The prepass is explicitly tagged `validationOnly`, has `measurementSupported:false`, and cannot be replayed. Only its first owned-text overflow may reject a candidate. Every passing prepass is followed by a context reset, full recording, and all existing coverage/readability/geometry checks. Caller-owned resource counters are copied for the prepass.

Support-plane calculations retain every normal/candidate and their order; only each point's subtraction of the same circle center is performed once per solve. Bounds use an ordered single pass with the same validation and Math.min/Math.max behavior, including signed zero. This removes the engine's incidental spread-argument limit without changing the explicit geometry/event/glyph ceilings. Two fixed Intl.Segmenter instances reuse the identical default locale and granularity; each call obtains a new independent segment iterator. No segmentation results are memoized. Curve/solver/proof cache capacities and all acceptance thresholds remain unchanged.

Run `node dev/avoidance/layouts-a-adaptive-perf.cjs` alone for the mandatory three planning warmups, six samples at 100 and 1000 cuts/regions, and separate single-cut 100/1000-region stress cases. The script reports cold timing separately; acceptance uses measured planning p95 <=2 times the same-input staged baseline and additional render p95 <=3ms. Pilot results are not official performance acceptance.


## Final performance design: bounded exact-key reuse and verified support search

The explicit adaptive path for the eight revised adapters uses `supportHull:true` in native full/hold and reconstructed recipe solves. Search projects the convex hull of the original measured points when it has at least three vertices; every original polygon edge still contributes normals in the original order, the ranking rule remains the same, and every candidate is accepted only by the original full-polygon circle test, original stage/fitBounds check and any fixed-field callback. The other eighteen adapters, basic/default solves, and native joint solves without the explicit adaptive opt-in retain the original search. The solver cache includes the opt-in mode in its key, and callback solves still bypass it. Floating-point support calculations can differ from the old all-point search in principle; this is not claimed as general bitwise equivalence. Candidate-matched regressions and pixel comparisons determine actual observed differences.

Native preparation continues using the original exact context key and immutable whole native program. Its existing 64MiB encoded-data ceiling and 2048 total-key ceiling now include resident entries, null-program ghost entries, exact key strings, frequency/program-size/entry-size metadata and a fixed 64-byte request-counter reservation. Resident entries have a 56MiB sublimit within that same total, leaving room for history; small workloads can therefore cache less native payload than under the former policy. No secondary cache capacity is added. Equal-frequency incoming programs preserve residents; a higher-frequency program must qualify against every required victim before payload eviction. At an all-resident entry ceiling, the key slot and payload evictions are planned together. Ghosts retain no program. Oversize results remain uncached frozen return values, and unsupported/throwing recordings are never reused as successful programs.

Frequency saturates at255 and halves after4096 requests, so inactive projects lose priority. The executed synthetic1000-key scan retained807 residents; in that fixture the next project reached807 hits by its fifth pass and a return to the first project reached713 hits on its third pass and807 on its fourth. These are finite observed transitions, not fixed pass-count guarantees for arbitrary inputs. Font revision and explicit clear remove both resident and ghost state. All size statistics describe the accounted encoding, not actual JavaScript heap consumption.

The runtime circle check skips its original edge loop only when a finite ordinary-coordinate bounding box has an axis gap beyond a conservative floating-point guard. Convex-envelope coverage skips its original vertex loop only when the entire polygon bounding rectangle is strictly inside every envelope half-plane with a rounding guard. Boundaries, uncertain/nonfinite values and empty individual polygons preserve the original fallback semantics. No source geometry or AA padding is removed from full recordings.

Filmstrip/ticket alone use the owned-text prepass; other recipes go directly through the full recorder and original owned check. Within that explicitly non-certificate prepass, ordinary-coordinate glyphs may omit the two-device-pixel AA hull because the owned check reads the unchanged un-clipped ink polygons. Affine, font metrics, stroke, source order, clipping state and resource validation remain active; uncertain coordinates use the original hull. Passing candidates always receive full recording and all quality/proof checks. Grapheme/word segmenters initialize lazily; fully ASCII `flat` calls use an equivalent whitespace removal path, while Unicode keeps the original grapheme segmentation.

The circle/arc/rounded-rectangle recorder passes its already validated transform snapshot to the event writer. No Canvas operation occurs between acquisition and event creation; the writer retains its affine validation and all event/state/resource checks. Text and other adapters keep their existing acquisition path. This only removes the second identical getTransform call; the full recorded geometry and raster guards remain unchanged. The executed shape probe compared1,040 full/prepass outcomes including invalid and degenerate inputs without a value/diagnostic difference.
