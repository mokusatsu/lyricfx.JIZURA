## Source facts and smallest proposed change

09a's nativeDOriginalRoot expression includes tiles/balloons/magnets and others, but not bulbs. Without original-root admission, A.record resets its private measurement Canvas with setTransform(...getTransform()) and takes matrix(c) as nativeRoot. That reconstruction can produce M' different from the original live root M. SOURCE35/36 and31/32 established this failure mode for other exact source paths; it is a risk for bulbs, not measured bulbs transport failure yet. The generic clipless D replay branch already preserves a destination's current live root when it equals e.nativeTransform.root, applies an inverse-root translation for nonzero stage delta, then repeats local native operations. No replay body change is needed initially.

Second independent seam: recorder=renderer.makeEnv(proxy,env.plan,env.cut,env.sc,{...env,ctx:proxy,...}) receives the already effective env.fx in the spread. makeEnv Object.assign includes that value, then multiplies its motion by cut.motionScale again when motionScale<1. A native caller's effective motion therefore gets scaled twice in the reconstructed recorder. This conclusion follows the actual Object.assign/makeEnv source; it is not inferred merely from balloons' special branch. Bulbs itself uses native q/out/lt independently of fx.motion, but mainDraw delegates original enter/hold/exit and drawFx. In particular source HOLD.jitter uses env.fx.motion; source mainDraw also independently damps glyph transforms by cut.motionScale. Losing one factor or duplicating a factor changes the original pipeline. effectFx overrides must be preserved as the original effective object, not rebuilt from plan.fx.

Proposed isolated implementation after parent gate: reuse the exact accepted SOURCE50 D pack, add one bulbs-only admission predicate in an isolated09a copy, include it in nativeDOriginalRoot, and restore recorder.fx=env.fx only for that admitted bulbs source/renderer/pass. Keep the balloons branch and every other predicate/event/replay operation byte-identical. No renderer, camera, source painting/geometry/fonts/clocks, 09a replay body, generic makeEnv, D transport identity registry or adapter registration change. Preserve source50 hashes and inverse ledger separately.

Initial explicit scope: placementLayoutsD true, other A/B/C flags absent, layout bulbs with the unchanged registered native source and stock renderer drawCut/makeEnv; pass main/A/B; ordinary finite invertible roots/context admitted by existing A.affine/text/filter/shadow guards; native enter=cut, exit=cut, treat=none; hold in still/jitter/breathe. These holds are independently source-backed: plateHold permits all three; jitter supplies pure seeded charFn supported by itemGeometry; breathe changes original item size/tracking without raw spatial filters. Include jitter precisely so the effectiveFX fix has a visible motion-dependent test, not only a no-op still fixture. Preserve any original finite source fx/effectFx values and actual motionScale. Do not force either motion or size to1. Cameras are not rewritten or fixed to push: this is transport at the supplied actual root, not a lifetime camera safety bound.

Other effects/animations are not silently normalized. For flagged bulbs outside this pilot, return an explicit UNSUPPORTED_D_BULBS_TRANSPORT before recording/replay, with the unmodified native path available only as a separate baseline—not as an avoidance success. Existing unsupported text filters/shadows/pieceFns/raw clips etc retain their exact codes and incomplete program status. If catalog is partial-budget, preserve the partial catalog and all captured events/diagnostics but do not label the transport qualification complete. Add no permissive fallback. Unflagged normal bulbs and every other D path retain existing behavior. Parent may choose a narrower still-only first gate, but then jitter/nontrivial FX cases must remain explicitly unsupported and effectiveFX preservation still requires direct value/identity comparison; no claimed broad animation parity.

## Raw size and failure preservation

SOURCE50 JSON is341,256,701 bytes despite its ~19MB gzip and3.6MB XZ. Do not append a comparable transport matrix and then JSON.stringify one giant aggregate; Node's single-string ceiling is independent of compressed size. Future harness should stream a manifest plus separate gzip JSON chunks per fixture and small tuple batch. Do not stringify the full growing results array at exit.

Each browser evaluation returns one native/zero/moved comparison tuple (or at most a predeclared small batch). Parent Node immediately serializes that complete tuple, writes a new exclusive SHM chunk, records exact uncompressed/gzip bytes and SHA256, writes/updates a small durable manifest, and releases that tuple before acquiring the next. Keep every source call, matrix, item, catalog, paint record, raw alpha, diagnostics, expected/actual hash and failure detail in its chunk. Do not reduce records to hash-only proof. The manifest carries stable HTML/runtime/font/source pins, ordered tuple IDs, expected coverage, chunk checksums, completed/failed/pending counts and final POSTpin result. Append a partial exception chunk before closing browser; never delete prior chunks. A partial manifest remains partial and never becomes pass because timeout or process exit omitted pending cases.

Bound the serialized tuple payload, e.g.8MiB and explicit per-tuple paint/event counts. If an ordinary tuple exceeds the chosen output budget, retain a dedicated partial/budget failure descriptor and the already-written observations; split its observation arrays into numbered lossless subchunks instead of dropping fields or raising a single-string ceiling. Small per-tuple native programs need not share one giant program snapshot; preserve full values in chunks with exact references. Test the chunk manifest/reassembly with static small data and check that all expected IDs and counts survive; that is a storage test, not an application pass. Raw writes stay parent SHM, later parent lossless archive/reproduction review. No stdout dump of all observations, no screenshots as certificates, no formal performance/heap claim.
