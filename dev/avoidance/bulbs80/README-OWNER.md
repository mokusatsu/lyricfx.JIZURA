# Unregistered model ownership and detail-off experiments

These three JavaScript files are verbatim copies of the reviewed80n source-only prototype/test. They are not loaded by build.py, HTML, renderer, adapter registry, finalizer, cache or UI. No certificate or frame admission is issued. The owner module requires the reviewed80n compiler with its externalAccounting callback contract, existing source/proof/geometry/quality/local helpers and stock browser context; those external prototype dependencies are not installed by this checkpoint. The normal replay also requires that external helper environment. These files are not a standalone product path.

Run `node dev/avoidance/bulbs80/model-owner-test.cjs` for41independent mock-compiler checks. This validates key ownership, eviction/reprepare, simultaneous serialized accounting, context/dependency rejection and synchronous borrow behavior; it does not exercise Canvas or the genuine compiler.

The owner accepts only models compiled internally through its captured compiler. Opaque handles refer to at most2resident entries; eviction invalidates old handles. Geometry keys preserve exact Float64 values and all ordinary plan data except known finalization fields and region center/radius. Font/helper/context dependencies are checked before and after preparation. Normal-font revision and FontFace/catalogue differences invalidate old models. Borrow is synchronous, rejects reentry/async, counts before/after snapshots and returned data, and is explicitly a preparation-stage API. Current ownership requires the same renderer and preparation Canvas; use on a separate drawing context is not qualified.

`destination-normal80.js` keeps all clock/CTM/support/held calculations but defaults to diagnostic=false. It omits root/glyph-matrix detail arrays while preserving their computation counters. diagnostic=true retains those arrays. Repeated serialized accounting remains; this is not an accepted normal frame/circle/UI performance implementation.

The parent independently checked the80n same-runtime experiment:30pins,18raw records and both hashes; the base model matched old80m except timing; a same-renderer/Canvas/seed1205 text change caused one compile, while both circle edits reused a handle with zero additional compiles. Normal/diagnostic semantics matched for base and duplicate inputs;4162exact Fraction quality predicates and strict circle/stage conditions passed. Revision-only clearing was a separate negative. The actual J.addUserFont API changed dela to another already-loaded pinned family, rejected the old handle before its callback, and produced a new model with different actual CSS. No new-font placement acceptance was claimed. Eviction rejected old use and one explicit prepare recovered.
