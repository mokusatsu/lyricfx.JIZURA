# Domino whole-clock candidate compiler82i

Unregistered source-only generator over existing tilesProof48.clock. Dependencies82a/b/c/d and82h candidate arithmetic. This version of the candidate module adds only a retained serialized reservation query and bounded typed insufficient-space constraint details. No product registration, certificate, owner or UI binding.

`node compiler-test.cjs /path/to/82c/affine-support82.js` runs34 mock wiring checks. This test is not actual Canvas or a new proof of the native clock enumerator. The compiler itself obtains clocks directly from Q.clock, checks reachable preimage/firstTime correspondence and selectedPass counts, then consumes every active own once in original order. No frame rendering or paint spy occurs.

Current plan/cut signature and metrics revision are checked on resume. These are basic source-only checks, not complete font/source/private-owner admission. Caller must supply a dedicated context and stock renderer. No context is yielded; each own's save/restore and temporary sample/environment release completes before yield. Generator cancel/exception calls candidate cancellation. The final result proposes a source-Y candidate only; allclock actual shifted-CTM safety and X identity remain mandatory later gates. Ordinary circle/two-row avoidance is not added.

Accounting includes full clocks (queryBits/preimages), plan/cut, expected list, exact signature, current own/state, current environment data fields, current sample, candidate accumulator and caller reservation. Overlapping reservations are deliberately counted twice. Context backing store, native function closure heap and encoder temporary heap are outside this serialized definition; the cap remains8MiB. This conservative experimental accounting may be slow: source signatures are reencoded at resume and reservations repeatedly measured. Representative timings must report that cost before normal-use claims. No total-model/per-frame replay is installed.
