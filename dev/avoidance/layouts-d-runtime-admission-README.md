# Optional D runtime admission regression

These tests exercise the three-source80s bridge in the normal Japanese/English build. They do not install bulbs80 or certify a new avoidance implementation. The browser uses actual J.plan lineage, actual sync finalizer, actual completed-plan codec/cache and existing native render paths. A pinned local eight-font fixture gives repeatable font resources. Qt launch/service adapter and all raw evidence remain outside Git.

`layouts-d-runtime-admission-pure.cjs` runs80 focused VM assertions against the actual current src files (complete09k registry, actual09a entry/restoration and09g hit/collector/clear fragments). This is not full API/Canvas evidence.

The repository-external reviewed `probe.cjs` is the local actual browser orchestrator, loading the built index.html/en/index.html, explicit-language fixture and browser test source. Its protected Qt wrapper uses a run-specific release token and pinned evidence namespace; those environment-specific paths are not committed in repository test sources. Both pages must have matching actual UI and plan language, and all8 pinned fonts loaded. The wrapper refuses a live9333 service and keeps the standard sandbox/protections. No media/screenshot/public access.

The run manifest `layouts-d-runtime-admission-fixtures.json` pins expected renderable safety before execution. A precondition failure preserves the plans/diagnostics and stops before any frame; insufficient-space is never silently accepted as a drawable legacy case. Balloons uses the historical native804 bunch4glyph/ghost fixture (source-stage feasibility evidence, not new runtime qualification).

For callback-free existing stickyNotes(C), balloons(D bunch native4glyph) and fisheye(D dedicated), each language uses cold finalize, same-final prior return, and original-input completed decode hit. Tests require real staged trajectories, exact cold/decoded JSON plus alias/property-descriptor graph hashes, immutable/detached decoded output, cache-store/hit behavior and three cold/decoded ordinary-renderer RGBA hashes. Existing safe/insufficient geometry decisions are preserved; matching hashes do not establish new geometry safety. No candidate/clock simplification is made by these tests.

The separate test-only wall adapter emits an explicitly insufficient-space trajectory with a test-only certificate. It is never rendered and must not be counted as safe bulbs or placement qualification. Its private WeakSets/resident IDs allow testing owned prior success versus decoded alias rejection. Actual cache/codecs must reject decoded aliases before successful-hit bookkeeping and refinalize genuine original J.plan input; false/throw and model-residency loss must fail admission; originalCuts must be restored without placementTrajectory. A serialized foreign input must still fail SOURCE_PLAN_REQUIRED. Adding a separate callback-bearing registry entry must invalidate the dependency key; rows retain fifth callback identity. Helper property must remain nonwritable/nonconfigurable. This adapter is installed only by the test page and is not registered in product sources.

Full raw API results are saved before assertions, with decoded/gzip hashes, source/build/font/runtime pins before/after, and failed runs retained. Diagnostic limits are64MiB/record,512MiB decoded total,64MiB gzip total; these do not change the existing product cache/proof budgets. No timing is used for acceptance. Parent source review and explicit Qt release are required before running this local harness.

Still unfinished after this bridge: real bulbs80 opaque ownership/finalized-plan binding, callback no-compile/no-paint proof, normal source frame registration, callback admission for both upper paths, decoded miss/resident-model reuse, eviction fail-before-bitmap and ordinary-finalize recovery. The new bulbs failure path must also detect its own insufficient/unsupported restored-original diagnostic and reject before bitmap. Existing other-layout catch/fallback behavior must remain unchanged. UI async publication and shared Canvas exception restoration redesign are separate.
