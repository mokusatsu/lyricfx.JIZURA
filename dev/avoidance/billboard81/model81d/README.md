# Billboard input-derived model81d — offline source-only stage

No product registration, renderer hook, certificate/cache/owner or UI connection. No Canvas execution of these new modules yet. Native helper81a/b/c fidelity was independently checked across the base-JA full250 clock; that result does not prove this model.

`prepare-source.py` adds only a readonly access to the original lexical `brk` operation. Removing that addition reproduces the accepted81c source exactly. Normal render is unchanged. `recipe-descriptor81.js` derives the fresh native size using the accepted original helpers and builds7 board/font-stage recipes from the current text and stage. Native size is attempted first, then .72; there is no fixed text, seed or circle exception. Initial text domain is2..16 single-codepoint graphemes, no spaces/newlines/combining/control format characters; unsupported data is rejected rather than normalized. Ground is fixed. Descriptor parts are potential supports, not actual paint counts.

`scalar-support81.js` uses actual current root/item/glyph Canvas transform operations and real TextMetrics, with existing +1fontpx/+2devicepx conditional foundation through the existing compiler arithmetic. Stroke width is assigned/read back from Canvas before padding; no invented epsilon. Main-only cones/illumination conservatively use the source's existing board clip. No paint, spy, radial-gradient emulation or paint-atom calculation. Main entrance delay and ghost/alpha gates are explicit. New recipe source binding and native/direct oracle are not yet implemented.

`model-compiler81.js` evaluates every P.clock active own state for all7 recipes, retaining actual roots/schedule and semantic owner unions. The current sample includes the compiler's live reservation in the same8MiB serialized budget. Candidate filtering/witnesses are also counted; witness storage is bounded16 with a full failure count. Conflicting conservative bounds yield `BILLBOARD81D_CONSERVATIVE_INSUFFICIENT`; this is a conservative refusal, not proof that no layout exists. A clear bound remains `quality-unproved`, never safe. No geometry from stored raw is used as runtime input.

This implementation is an offline exploration. Full serialized accounting is intentionally expensive. It must not be installed per frame or on synchronous UI. Cold compile time, future ordinary frame overhead and UI preparation are separate unmeasured gates. General source/dependency/pristine guards and owned admission are incomplete, so standalone scope checks do not establish a runtime safety boundary.

Pure checks: descriptor17819; scalar-support4100; aggregate146 (synthetic3states/9own×7). They cover text rejection, native-first7 recipes, inventory/fixed ground, matrix/metric skeleton gates/no paint, current reservation rejection, normal/diagnostic aggregate equality, and conservative large-circle ground rejection. Synthetic split/layout/Canvas arithmetic are not real Canvas/font/727clock qualification. Initial pure harness failures (newline counted by stub; duplicate lexical identifier) were corrected in harness only.

Next gate: current-input fresh native reference, full glyph/metadata order, native actualCTM/metric support containment on all727own; fresh reference for each recipe with source-only recipe binding and unchanged source clip/material/RNG; preserve all prior quality predicates. Existing pilot raw can validate native recipe subset but cannot certify the new recipes. Real Canvas is pending parent source/pins review and explicit release. No media/public work.
