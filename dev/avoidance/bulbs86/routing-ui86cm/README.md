# Selected-cut legacy routing and screenshot preflight86cm

Parent final source review found two related regressions. UI area/detail guards rejected every bulbs cut whenever any other bulbs cut in the plan used automatic avoidance. The new controller also missed two original finalizer preservation conditions: private project line locks and emphasis. A locked automatic bulbs cut can have `placementLocked===false`; its lock exists only in the composed plan's private lineage. This correction shares that preservation decision without exposing or rebuilding private state.

## Source behavior

`src/09a_placement.js` now defines the small internal `placementCutPreserved86cm(plan,cut,lineage)` helper. Its known-lineage predicate is the exact old `PRESERVED_LEGACY` disjunction: avoidance disabled, lineage.locked includes index, manual/notation area, placementLocked, or emphasis. The finalizer's existing conditional calls this helper with its existing lineage. Finalizer source validation still happens first; its treatment of valid plans is unchanged.

A nonwritable `A.placementCutPreserved86cm(plan,cut)` accessor returns only true/false/null. It requires the cut to belong to the supplied plan and never exposes the WeakMap, lock arrays, original cuts or setters. Self-contained explicit preserved conditions remain preserved; unknown automatic lineage returns null. Null is not permission for stock/output bypass: the bulbs selector treats it as a target, so an unproved automatic clone remains refused/prepared through the existing boundary. In particular, a detached copy of a privately locked automatic cut cannot pretend its lost lock provenance authorizes output.

Controller `targetsCut(plan,cut)` uses the same accessor plus the existing enabled/nonempty avoidance requirements. `targetsPreview` and `targetsFrame` use it consistently, retaining existing root/trail timing and hidden-layer behavior. UI area checks the same first line cut that its original seek uses; detail checks only its exact selected line/part. They retain the existing visible-layer UI preparation condition. A different automatic bulbs cut does not block manual/notation/locked/emphasis editing. Full-plan output preflight remains conservative when any actual target is present; allowing one selected editor does not permit exporting the mixed target plan.

Screenshot now calls the existing common `J.assertPlanOutputSupported` at the first statement in its try block, before filename/output-size/Canvas/Renderer/glyph-resolution changes. Target plans allocate none of these resources. Hidden lyrics, disabled avoidance, other effects and preserved-only plans retain their existing screenshot flow. No screenshot image is generated by the verification.

All product controller/UI additions reproduce through `product-ui86ci/generate.py`; generated JS matches `src/`, and both ordinary JA/EN rebuilds are byte-identical. The shared placement helper is ordinary source in09a. There is no shared renderer or exception-stack redesign, layout generalization, geometry/clock/quality relaxation, export bypass or mutable plan-lineage API.
