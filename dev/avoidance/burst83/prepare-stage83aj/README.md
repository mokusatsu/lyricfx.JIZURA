# Burst formal-stage preparation marker 83aj

Unregistered stage-only adapter, derived from the tested Domino82t staging contract. It never returns a safe trajectory or grants frame authority. Run `python3 run-tests.py /path/to/repository`.

The real 09k registry/catch/admission test has 22 checks, with synthetic normalized working plans. 09k's exact `fullStagePlacement`, `placementUnits`, and `placementLayoutsD` true flags are validated before those three known preparation outputs are projected away. Every other unknown input field remains in the exact source key. Forged placement output is rejected. The adapter always throws PREPARE_REQUIRED after capture; 09k restores the original cut, emits the callback-owned runtime-admission marker, and admission returns false. Changed text/circle/font yields a different staged key. Revision, face identity, and generation changes drop stale stage data, after which a fresh finalization can stage again.

The stage contains a private dense frozen clone and exact key, limited to 256KiB serialized storage/work. This is a stage-only subcap and must later be combined with owner/model/plan/issuer reservations under 8MiB; it is not additional memory allowance. Stage stats disclose key/byte counts, not the stored plan. Scope checks are normalization checks rather than Burst source/geometry qualification. The public factory, mock inputs, and prior raw cannot grant authority.

Formal J.plan/09a/09g cache and actual Renderer refusal remain untested here. The actual private controller's canonical-time route and sample-clock proof do not yet justify a generic trajectory over every real time. Readiness transfer, safe trajectory issue, and UI registration are deliberately absent. No new model or video is generated by these tests.
